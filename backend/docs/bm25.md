# BM25 Ranking — Technical Documentation

## Overview

Phase 7 replaces Phase 6's TF-IDF cosine similarity with **BM25**, a
probabilistic relevance-ranking function widely used in information
retrieval (originally developed for the Okapi system at City University
London in the 1990s).

```
Phase 5:  matched terms + raw frequency → integer score
Phase 6:  TF-IDF vectors + cosine similarity → float [0, 1]
Phase 7:  BM25 with tunable saturation + length norm → float [0, ∞)
```

---

## BM25 Formula

```
BM25(D, Q) = Σ IDF(t) × f(t,D) × (k1 + 1) / (f(t,D) + k1 × (1 - b + b × |D| / avgdl))
```

Where:

| Symbol | Meaning |
|--------|---------|
| `f(t,D)` | Frequency of term *t* in document *D* |
| `\|D\|` | Document length (total tokens) |
| `avgdl` | Average document length across all indexed documents |
| `k1` | Term-frequency saturation parameter (default 1.2) |
| `b` | Document-length normalization parameter (default 0.75) |

The sum is over all query terms that appear in the candidate document.

---

## BM25 IDF

```
IDF(t) = log(1 + (N - DF(t) + 0.5) / (DF(t) + 0.5))
```

This differs from Phase 6's TF-IDF IDF:

| | TF-IDF (Phase 6) | BM25 (Phase 7) |
|--|---|---|
| Formula | `log(N / DF)` | `log(1 + (N - DF + 0.5) / (DF + 0.5))` |
| When DF = N | IDF = 0 (no contribution) | IDF > 0 (small positive) |
| Smoothing | None | +0.5 additive smoothing |

The BM25 IDF never becomes exactly zero — a term appearing in every
document still contributes a small positive weight.  This prevents
terms from being completely discounted.

---

## Parameter: k1 (Term-Frequency Saturation)

`k1` controls how quickly term-frequency saturates.

```
k1 = 0   → TF has no effect beyond term presence
k1 = 1.2 → default, moderate saturation
k1 = 2.0 → slower saturation, TF differences matter more
```

### How it works

The BM25 term score numerator is `f × (k1 + 1)` and the denominator
includes `f + k1 × normalization`.  As `f` grows large:

```
f × (k1 + 1) / (f + k1 × norm) → (k1 + 1) / 1 = k1 + 1
```

So the score approaches `IDF × (k1 + 1)` as a ceiling.  The higher
`k1` is, the more slowly this ceiling is reached — meaning additional
occurrences continue to matter for longer.

| TF | Score (k1=0) | Score (k1=1.2) | Score (k1=3.0) |
|----|-------------|----------------|----------------|
| 1  | IDF × 1     | IDF × 1.0      | IDF × 1.0      |
| 5  | IDF × 1     | IDF × 1.65     | IDF × 2.14     |
| 50 | IDF × 1     | IDF × 2.12     | IDF × 3.51     |

Validation: `k1 >= 0`

---

## Parameter: b (Document-Length Normalization)

`b` controls how strongly document length affects ranking.

```
b = 0    → no length normalization
b = 0.75 → default, moderate normalization
b = 1    → full normalization proportional to length
```

### How it works

The normalization factor in the denominator is:

```
1 - b + b × |D| / avgdl
```

When `b = 0`: factor = `1` (constant — length doesn't matter).

When `b = 1`: factor = `|D| / avgdl` (fully proportional to length).

A document twice as long as average has its score penalised because
long documents are expected to contain more terms by chance.

| Document Length | Factor (b=0) | Factor (b=0.75) | Factor (b=1) |
|-----------------|-------------|-----------------|-------------|
| 0.5 × avgdl    | 1.0         | 0.625           | 0.5         |
| 1.0 × avgdl    | 1.0         | 1.0             | 1.0         |
| 2.0 × avgdl    | 1.0         | 1.75            | 2.0         |

Validation: `0 <= b <= 1`

## Configuration

BM25 parameters are configured via application settings:

```env
BM25_K1=1.2
BM25_B=0.75
```

These are read from `app/config/settings.py` and passed to the
`SearchEngine`.  They can be overridden via environment variables.

## Phase 5 → Phase 6 → Phase 7 Comparison

| Aspect | Phase 5 | Phase 6 (TF-IDF) | Phase 7 (BM25) |
|--------|---------|-------------------|----------------|
| Score type | Integer | Float [0, 1] | Float [0, ∞) |
| Primary criterion | Matched term count | Cosine similarity | BM25 score |
| TF handling | Raw count | Logarithmic | Saturating (k1) |
| IDF | Not used | log(N/DF) | log(1+(N-DF+0.5)/(DF+0.5)) |
| Length normalization | None | Cosine (magnitude) | Tunable (b) |
| Parameters | None | None | k1, b |
| DF=N behaviour | Term counts normally | IDF=0, zero contribution | IDF>0, small contribution |

---

## Why BM25 over TF-IDF

BM25 is generally considered a stronger lexical ranking baseline:

1. **Controlled saturation** — TF-IDF uses `1 + log(f)` which
   saturates somewhat, but BM25's saturation is *tunable* via `k1`.

2. **Explicit length normalization** — TF-IDF uses cosine similarity
   which normalizes by vector magnitude.  BM25's `b` parameter gives
   direct control over how much document length matters.

3. **IDF smoothing** — BM25's IDF formula avoids the TF-IDF problem
   where a term in every document contributes exactly zero.

4. **Industry standard** — BM25 (or variants) is the default
   lexical ranker in Elasticsearch, Lucene/Solr, and most production
   search systems.

## Architecture

The ranking change is isolated to the scoring layer:

```
QueryParser          (unchanged — Phase 3)
      ↓
CandidateRetrieval   (unchanged — Phase 4/5)
      ↓
BM25 Ranker          (NEW — Phase 7)
  ├── bm25.py        (math: IDF, term score, full score)
  └── bm25_ranker.py (scoring pipeline)
      ↓
SearchEngine         (updated to use BM25 ranker)
      ↓
SearchService        (unchanged — uses score field)
```

The TF-IDF implementation (`tfidf.py`, `tfidf_ranker.py`) is preserved
for experimentation and comparison.

---

## Score Range

Unlike cosine similarity which is bounded [0, 1], BM25 scores have
**no fixed upper bound**.  A document matching many rare query terms
with high frequency can produce scores well above 1.0:

```
Score: 0.42     (one common term match)
Score: 4.83     (multiple rare term matches)
Score: 12.7     (many rare terms, high TF)
```

## API Impact

The API contract is unchanged:

```json
{
  "query": "python",
  "total": 3,
  "page": 1,
  "limit": 10,
  "results": [
    {
      "document_id": 5,
      "title": "Python Guide",
      "url": "https://example.com/python",
      "score": 4.8271
    }
  ],
  "took_ms": 1.42
}
```

The only visible change: `score` values are now BM25 relevance scores
instead of TF-IDF cosine similarity values.

---

## Limitations

Phase 7 does **not** implement:

- **Phrase search** — "python web" matches either term independently
- **Field weighting** — title vs body (Phase 8)
- **Snippet generation** — no highlighted excerpts (Phase 9)
- **Crawler** — no URL fetching (Phase 10)
- **Semantic search** — no embeddings or vectors
- **Fuzzy search** — exact matches only
- **Query-time parameter tuning** — no `?k1=` or `?b=` API parameters
